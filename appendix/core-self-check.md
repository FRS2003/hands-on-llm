# 核心知识自测 Self-Check（结合本仓库真实实验）

> **自测方法**：先自己给出结论与原理，再对照下面要点，并用仓库里跑出的真实数字验证理解；所有数字都能在对应模块（主要是 02）找到日志、曲线与评测脚本。

## 一、训练流程

**Q1：预训练和 SFT 的区别？**
A：数据形式、目标、学习率、起点都不同。预训练用海量纯文本做 next-token 预测学语言知识，lr 5e-4、从零开始；SFT 用(指令,回答)配对、只对回答算 loss，lr 1e-5、从预训练权重热启动。本项目的消融：只预训练的模型让写斐波那契只会续写一串数字，SFT 后才会以助手身份分点作答、用代码块。

**Q2：为什么越靠后的阶段学习率越小？**
A：防止灾难性遗忘。预训练是白纸要大步学；SFT 时语言能力已具备只需轻调行为；到 DPO 只调偏好，本项目取 lr=4e-8。完整 lr 序列：5e-4 → 1e-5(LoRA 1e-4 因只训少量新参数) → 4e-8。

**Q3：DPO 的 loss 为什么一开始约等于 0.693？**
A：初始 policy 与 reference 完全相同，模型对 chosen/rejected 五五开，即好答案概率 0.5，-ln0.5=ln2≈0.693。在 17,166 对数据上，训练起点确实在 0.69 附近，随后区间均值 0.642→0.620，理论与实验吻合。

**Q4：DPO/对齐会不会让模型学会新知识？**
A：不会，它只改偏好/风格、不改知识。实验中 DPO 后回答更简洁收敛，但本来写错的斐波那契依然错——对齐调"怎么说"，不调"知道什么"。

**Q5：GRPO 和 PPO、DPO 的区别？为什么慢？**
A：DPO 要现成好坏对、免训练奖励模型；PPO 要价值网络(critic)；GRPO 对一个问题自采 G 条、用组内均值/标准差算相对优势，省掉 critic。慢在每步要在线 rollout 生成 G 条回答。本项目用纯规则奖励替代 1.8B 奖励模型：先用 14 项 tensor 自检验证组内优势中心化、KL、初始 ratio=1、loss 可反传，再在 3080Ti 上真实训练 300 步（21.7 min、≈4.3 s/步，每步为 2 个 prompt 各在线生成 4 条），实测组内优势均值**严格为 0**、平均 |KL|≈0.005（β=0.1 锚定、几乎不偏离 SFT 起点）、同 prompt/同种子前后对比规则分 **0.109→0.290**。

**Q5b：什么是可验证奖励（RLVR）？为什么 RL 前要先把 SFT 做到"甜区"？**
A：RLVR 用可程序化判分的结果当奖励（数学答案、代码单测），答对 +1、答错 0，不需要额外奖励模型、也难被 reward hacking。关键前提是 **RL 不注入新知识，只重新分配已有能力的概率**：若模型对某题采样 G 次全错，组内奖励全 0、优势恒 0、这题就没有梯度。所以要先 SFT 到"采样能偶尔答对"的半会甜区，RL 才能把正确采样的概率放大（在一位加法任务上，独立 120 题 greedy 0.633→0.792、采样 0.503→0.603）。任务超出能力边界（两位加法不会进位、组内全错）时 RL 无效；学习率过大、β-KL 锚定太弱还会策略崩溃（greedy 一度崩到 0.03）。这也解释了为什么数学/代码 RL 有效：基座其实已具备推理潜力，RL 只是把它"激发并稳定"出来。
**Q6：loss 越低模型越好吗？**
A：不是。loss 只衡量拟合训练文本程度，生成质量要另开推理实测。本项目 SFT loss 到 2.2 时模型仍会胡说，且 DPO 因 batch=4 曲线噪声大，要看滑动平均而非单点。

## 二、架构与优化

**Q7：MHA/MQA/GQA 的区别，为什么 GQA 省显存？**
A：MHA 每 Q 头配独立 K/V；MQA 所有 Q 共享一组 K/V；GQA 分组共享，折中。省的是 KV Cache。手写模型为 8 Q 头、4 KV 头的 GQA。同骨架上的消融实测：训练侧（bs8、bf16）MHA/GQA/MQA 峰值显存 2623/2490/2312MB、吞吐 60/64/70 k tok/s，训练时省得有限（激活大头与 KV 头无关）；但推理 KV cache@4096 为 100.7/50.3/12.6MB、严格按 KV 头数 8:4:1，长上下文/高并发才是 GQA/MQA 省显存的主战场；bf16 比 fp32 再省 35–49% 显存、约 1.8× 吞吐。

**Q8：RoPE 是什么、相对位置怎么来的？**
A：对 Q、K 按位置做旋转变换，使注意力分数只依赖两 token 的相对位置差，外推性优于绝对位置编码。from_scratch 中手写了 precompute + apply 全过程并做了数值自检。

**Q9：bf16 为什么省显存、和 fp16 区别？**
A：16 位代替 32 位存中间结果，显存近半、提速；bf16 指数位多、动态范围大，不易梯度上溢/下溢，训练优先用 bf16。

**Q10：单卡显存不够怎么训？**
A：梯度累积等效大 batch（本项目用累积 8 步等效 batch 256）、bf16、梯度检查点、LoRA、减小 batch/序列长、GQA 压缩 KV Cache；多卡再上 DDP/ZeRO/TP/PP。

**Q11：LoRA 为什么只训极少量参数就有效？省多少？**
A：冻结 W，只学低秩增量 BA（W'=W+BA），适配新领域所需信息维度低，不需要满秩更新。实测：可训参数 63.91M→0.393M（0.61%），权重 132MB→0.78MB，显存 7.36→4.60GB。

## 三、框架与工程选型（03）

**Q12：LoRA 和 QLoRA、DoRA 怎么选？**
A：显存够优先全量或 LoRA；显存极紧用 QLoRA（4bit 基座+LoRA）；追求更高质量可试 DoRA。03 模块有八类 PEFT 在参数量/显存/精度/延迟上的对照表。

**Q13：DPO/KTO/ORPO/SimPO 怎么取舍？**
A：DPO 要成对偏好+参考模型；KTO 只要单条好坏标注、不要成对；ORPO 把 SFT 与偏好合一、免参考模型；SimPO 用平均对数概率、也免参考模型。选型看数据形态与算力。

**Q14：DDP/TP/PP/ZeRO 区别？**
A：DDP 每卡复制模型分数据、靠 all-reduce 同步梯度；TP 把单层矩阵切到多卡（层内并行，通信重）；PP 按层分段到不同卡（层间流水线，有 bubble）；ZeRO 把优化器状态/梯度/参数分片。03 有单卡显存/吞吐/通信折中表。

## 四、Agent（04）

**Q15：ReAct 是什么？为什么需要 Harness？**
A：Reason→Act→Observe 循环，让模型边推理边调工具。Harness 负责工具约束(curfew)、无进展检测、终止条件等"护栏"，避免模型空转或越权。mini_code_core 中实现了这套循环。

**Q16：长任务上下文爆了怎么办？**
A：分层上下文压缩：结构化摘要、大结果外置到文件只留占位、超限兜底；再加记忆系统把可复用经验沉淀、按需注入。04 的 context_manager/memory 有完整实现。

**Q17：多智能体怎么分工、安全怎么做？**
A：Supervisor 规划审批、Worker 微型循环执行、异步并发加三级失败处理。安全是分层过滤链：注入检测、操作边界、沙箱路径映射、分级确认、输出脱敏。

## 五、RAG（05）

**Q18：为什么要混合检索（BM25+稠密）？**
A：BM25 擅长精确关键词/专有名词，稠密向量擅长语义近义，单路都有盲区；双路召回后做分数归一化加权融合（本项目取 0.6 向量 + 0.4 BM25；RRF 按排名融合是另一种常见方式，区别见 05 文档），再交 Rerank 精排；05 有多种召回/融合/重排变体的 benchmark 对照与真实日志。

**Q19：HyDE 解决什么问题？**
A：问题往往很短、和文档表述有鸿沟；先让模型生成一个"假设答案"，用它去检索，语义更贴近文档，提高召回。

**Q20：怎么让 RAG 回答可信、怎么评测？**
A：要求带文献引文、答案可溯源；评测上建标注集，比较不同召回/融合/重排策略的 Recall@K 与命中率。05/evaluation 下有可复现脚本。
