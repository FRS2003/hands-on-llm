## 0. 先建立最重要的一张「全景图」

把训练一个大模型想象成**培养一个人**，每个阶段对应成长的一个阶段：

| 阶段 | 人生类比 | 模型在学什么 | 本项目是否复现 |
| --- | --- | --- | --- |
| **预训练 Pretrain** | 从小到大**博览群书**、海量阅读 | 学会语言规律、常识与世界知识（但还不会"听话答题"） | ✅ |
| **监督微调 SFT** | 请家教上培训班，学会**按题目格式作答** | 听懂指令、用对话格式回答问题 | ✅ |
| **LoRA** | 一种**省钱的补习方式**（不重学全部，只补关键一点点） | 以极低成本做领域 / 风格适配 | ✅ |
| **DPO** | 培养**品味**，在好答案与烂答案之间学会挑好的 | 对齐人类偏好，说得更得体、更有用 | ✅ |
| **GRPO / RLVR** | **大量实战刷题**，做对有奖励、自己跟自己比着进步 | 用奖励信号强化期望行为，可验证任务上实打实提分 | ✅ |

一条主线流程是这样的（箭头表示"在上一步成果上继续"）：

```
原始海量文本              问答配对数据            好/坏回答偏好数据         问题 + 可判分奖励
     │                       │                        │                      │
     ▼                       ▼                        ▼                      ▼
[预训练 Pretrain] →基座→ [监督微调 SFT] →会聊天→ [DPO 偏好对齐] →更得体→ [GRPO/RLVR 强化] →更强
   学语言 / 知识            学指令遵循               学偏好 / 风格            奖励信号下提分
                               ▲
                               │ LoRA 是 SFT（或任意阶段）的"低成本替代打法"，本身不是新阶段
```

**三句话记住本质：**

1. **Pretrain 让模型"有学问"，SFT 让它"会交流"，DPO 让它"有品味"，GRPO/RLVR 让它"在被奖励的方向上更强"。**
2. LoRA 不是一个新阶段，而是一种**少花算力办同样事的训练技巧**。
3. 在已经很强的模型上做 SFT / DPO 这类微调时，学习率要远小于预训练，轻轻调整即可，否则会把前面学到的能力冲垮（即**灾难性遗忘**）。

## 1. 预训练 Pretrain：模型到底在学什么？

### 1.1 本质：就是一个超级"完形填空"

预训练阶段模型只做一件事：**预测下一个词（Next Token Prediction）**。给它一句话的前半段，让它猜下一个 token：

```
输入："今天天气真"   →  模型应预测下一个词更可能是"好"，而不是"桌子"
```

它在几百万、上亿条文本上反复做"猜下一个词 → 对答案 → 改错"，慢慢就**内化了语法、事实和推理模式**。注意这个阶段喂的是**纯文本、没有问题-答案格式**，所以学到的是"语言本身"，而不是"如何回答问题"。

### 1.2 loss 是什么？为什么从 7+ 降到 2.5 很重要？

- **loss（损失）**：衡量"模型猜的下一个词"和"真实下一个词"差多远的数字，**越小越好**。用的是交叉熵，现阶段可以直接理解成**猜错的惩罚分**。
- 更直观的指标是**困惑度 PPL = e^loss**，即"模型平均在多少个候选词里纠结"。
  - medium 预训练结束 loss=2.53 → PPL ≈ e^2.53 ≈ **12.6**，即平均在十几个候选里挑（小模型这个水平正常）；
  - 训练刚开始 loss=7.31 → PPL ≈ 1495，等于完全瞎蒙。**从 1495 个里瞎蒙 → 十几个里挑，这就是"学会了语言"。**

### 1.3 对照真实实验（这是最该看懂的一组对照）

| 实验 | 数据量 | 步数 | 耗时 | loss 起→终 |
| --- | --- | --- | --- | --- |
| small 预训练 | 6 万条 | 3,750 | 10.3 分钟 | 7.73 → **3.35** |
| medium 预训练 | 15 万条 | 9,376 | 25.5 分钟 | 7.31 → **2.53** |

**同样的模型、同样的超参数，只是喂的数据多 2.5 倍，最终 loss 就从 3.35 降到 2.53，生成文本也明显更通顺。** 这就是一次干净的"**数据规模效应**"对照实验——它把"数据越多越好"这句口号变成了自己跑出来的曲线。

### 1.4 这一阶段的高频名词（一次性讲清）

- **from scratch（从零训练）**：初始权重随机、什么都不会，完全靠这批数据学起来（区别于"拿别人训好的模型继续训"）。
- **epoch（轮）**：把全部数据完整看一遍叫 1 个 epoch，设 2 就是看两遍。
- **batch / step**：一次喂 batch 条样本、更新一次参数叫一个 step，本实验 batch=32。
- **梯度累积 accumulation_steps=8**：显存小、一次塞不下那么多样本时，分 8 次算、攒够梯度再更新一次，**等效 batch = 32×8 = 256 的大 batch**（称"有效 batch"），是小显存训大模型的关键技巧。
- **学习率 lr=5e-4 + cosine 调度 + warmup**：lr 是"每次改错的步幅"；warmup 是开头先小步热身，cosine 是之后平滑地由大到小收尾，训练更稳。
- **bf16 混合精度**：全程用 32 位小数很占显存，bf16 用 16 位存中间结果，**显存近乎减半、速度更快、精度损失极小**，本项目全程使用。
- **AdamW**：最常用的优化器，决定"具体按梯度怎么改参数"，知道名字即可。

### 1.5 产出

得到一个 `pretrain_768.pth` 权重文件（约 132MB），这就是**基座模型**。关键是——**它此时还不会聊天**，下一节用一个消融现象来证明。

## 2. 监督微调 SFT：为什么"博览群书"之后还要"上培训班"？

### 2.1 一个最有说服力的现象（消融实验）

拿只做过预训练的模型，让它"用 Python 写斐波那契函数"，它输出的是：

```
。1, 2, 3, 5, 8, 9, 7, 9, 10, 5, 7, 9 ...（一串数字）
```

它没有在"回答问题"，只是在**续写**它认为最可能出现的文本——因为预训练里从没见过"问题→回答"这种结构。经过 SFT 之后，同一个模型会说："这是一个使用 Python 编写的函数：`python ...`"，即学会了自己是个"助手"、要按格式回应。

> 这种"只改变一个条件（做没做 SFT）、其余全部不变，来看差别"的实验，叫**消融实验（ablation）**，是证明"某个模块到底有没有用"的标准做法。

### 2.2 SFT 具体做了什么？

- 训练数据从"纯文本"换成 **(指令/问题, 理想回答) 的配对**，并套上固定的**对话模板（chat template）**，例如 `<|im_start|>user ... <|im_end|> <|im_start|>assistant ...`，让模型学会角色边界；
- **只对"助手回答"那部分算 loss，不对用户提问算 loss**（不需要模型学着怎么提问，只学怎么答）；
- **从预训练权重"热启动"**：不是从零开始，而是站在 pretrain 的肩膀上继续。

### 2.3 对照真实数字

| 实验 | 数据量 | 步数 | 耗时 | loss 起→终 |
| --- | --- | --- | --- | --- |
| small SFT | 2 万条 | 2,500 | 8.0 分钟 | 3.91 → **3.17** |
| medium SFT | 5 万条 | 6,250 | 19.6 分钟 | 2.82 → **2.21** |

### 2.4 核心问题：为什么 SFT 的学习率(1e-5)比预训练(5e-4)小这么多？

预训练时模型是"白纸"，要大步学语言；到 SFT 时模型已经掌握语言，只需**轻轻调整**行为方式，学习率太大会把预训练的成果冲坏（**灾难性遗忘**）。这就是"在强模型上微调要把学习率降下来"的原因。

### 2.5 Pretrain vs SFT 一张表分清

|  | 预训练 Pretrain | 监督微调 SFT |
| --- | --- | --- |
| 数据 | 海量纯文本 | 问题-回答配对 |
| 目标 | 预测下一个词，学知识 / 语言 | 学指令遵循、对话格式 |
| 学习率 | 大（5e-4） | 小（1e-5） |
| 从哪开始 | 随机权重（从零） | 从预训练权重继续 |
| 训完能干嘛 | 会续写，但不会答题 | 能以助手身份对话 |

## 3. LoRA：为什么只训练 0.61% 的参数就够了？

### 3.1 先讲痛点

全量微调（full SFT）要把模型 **63.91M 个参数全部更新**，每个任务存一个约 **132MB** 的新权重，训练时占约 **7.4GB** 显存。如果要给"医疗、法律、客服、人设……"各做一个专用模型，就得存 N 份 132MB、训 N 次全量——又慢又占空间。

### 3.2 LoRA 的思路（小白版）

**冻结住原模型、一个参数都不动；只在每层旁边挂两个很小的矩阵 A 和 B，让训练只发生在 A、B 上。**

- 数学上：原变换是 y = W·x，LoRA 改成 y = W·x + (B·A)·x，其中 W 冻住，只学 A、B；
- 直观比喻：原模型是一本**不能涂改的教科书**，LoRA 是给每章贴一张**薄薄的便利贴**做补充，换科目就换一叠便利贴、教科书本身不动；
- **低秩（low-rank）**：A、B 被设计得很"窄"（这个"窄"就是秩 / rank），所以参数量极小。直觉是："适配一个新领域所需的新信息维度其实不多，不必动用和原模型一样大的矩阵。"

### 3.3 真实对比（这组数字很能说明问题）

| 指标 | 全量 SFT | LoRA | 差距 |
| --- | --- | --- | --- |
| 可训练参数 | 63.91 M | **0.393 M** | LoRA 只有全量的 **0.61%（约 1/163）** |
| 保存的权重文件 | 132 MB | **0.779 MB** | 小约 169 倍 |
| 显存峰值 | 7.36 GB | **4.60 GB** | 省 37% |
| 2 万数据训练耗时 | 479 秒（2 轮） | 256 秒（3 轮） | 轮次更多反而更快 |

推理时把这张 0.78MB 的"便利贴"贴回冻结的原模型即可（复现命令 `--weight full_sft --lora_weight lora_demo` 验证了可正常加载、正常生成）。

### 3.4 loss 不降，为什么反而是"对的"？

在已训好的基座上、用**同分布**数据做 LoRA 时，loss 会一直在 2.21 附近波动、没有明显下降。**这不是失败：** 基座本来就已经会了，loss 自然不会再大降；而它没有升高、没有崩坏，正说明 LoRA **没有破坏原模型能力（无灾难性遗忘）**。LoRA 真正的威力要在"**专门领域小数据**"（如医疗问答）上才体现为明显提升。能讲清这一点，说明理解不止于"会跑脚本"。

### 3.5 什么时候用 LoRA

显存不够、要快速适配多个领域 / 风格 / 人设、希望每个任务只存一个几百 KB 的小文件并随时热插拔——这些都是 PEFT（参数高效微调）的典型场景，LoRA 是其中最主流的方法。

## 4. DPO：不训练"评委模型"，也能教模型品味

### 4.1 要解决什么问题

SFT 之后模型会回答了，但同一个问题往往有很多种答法，有好有坏。怎么让模型**稳定偏向人类更喜欢的那种**？这一步叫**偏好对齐**。

### 4.2 DPO 的思路：直接给它"好答案 vs 坏答案"

- 训练数据是三元组：(问题, 更好的回答 chosen, 更差的回答 rejected)，本项目用了 **17,166 对**；
- 训练目标用大白话说：**把好答案的概率往上抬、把坏答案的概率往下压，让两者差距越拉越开**；
- 它内部需要两个模型：
  - **policy（策略模型）**：正在被训练、不断调整的那个；
  - **reference（参考模型）**：训练前冻结的一份"快照"，当**参照物 / 锚**，防止 policy 为讨好偏好而跑偏太远（用 KL 散度衡量"偏了多远"并惩罚，KL 可理解成"两个输出分布之间的距离"）。

### 4.3 为什么 DPO loss 一开始正好是 0.693？（高频细节）

DPO 的 loss 初始值理论上等于 **-ln(2) ≈ 0.693**：

> 训练刚开始时 policy 和 reference 完全一样，模型对 chosen / rejected "**五五开**"，给好答案的概率是 0.5；而 -ln(0.5) = 0.693。

随着训练推进、模型越来越能区分好坏，loss 就往下走。本项目日志的起点确实就在 0.69 附近——**理论预测和真实实验对上了**，这种理论预测与真实实验吻合的细节，最能加深对原理的理解。

### 4.4 真实数据：为什么曲线"抖"、学习率为什么极小

- 区间均值：前半 **0.6415 → 后半 0.6201**，末步 0.43、最低 0.39，缓慢下降；
- **学习率只有 4e-8**（比 SFT 还小三个数量级）：偏好对齐是"微调品味"，步子一大就会冲垮 SFT 学到的能力，所以必须极小；
- **曲线噪声大**：因为 batch 只有 4，每次只看 4 对数据、波动天然大，所以要看**滑动平均 / 区间均值**的趋势，而不是纠结每个尖峰（曲线图里画移动平均线就是这个原因）；
- policy + reference 两个模型同时驻留显存，因此显存约 5.71GB，略高于单模型。

### 4.5 一个重要认知：DPO 只改"偏好 / 风格"，不增加知识

DPO 之后回答会更**简短、收敛、不啰嗦**，但它**依然可能把斐波那契函数写错**——因为 DPO 不教新知识，本来不会的还是不会。**对齐阶段调整的是"怎么说"，不是"知道什么"。** 能区分这两点，是理解深度的体现。

## 5. GRPO：让模型"自己跟自己比"来变强

### 5.1 有了 DPO 为什么还要 GRPO？

DPO 需要**事先准备好**"好 / 坏成对"的标注数据，成本高。GRPO（Group Relative Policy Optimization，由 DeepSeekMath / DeepSeek-R1 带火）换了个思路：**不需要别人喂好坏对，让模型自己批量生成、自己横向比较。**

### 5.2 工作流程（小白版）

对同一个问题：

1. 让当前模型**一次采样 G 个回答**（本项目取 G=4）；
2. 用一个**奖励函数**给这 G 个回答分别打分（奖励可以是规则分，如长度合适、格式正确、不重复；也可以是可验证结果，如数学答案对不对；还可以是奖励模型打分）；
3. **组内相对比较**：计算这组分数的均值和标准差，某个回答高于组内均值就鼓励、低于就抑制。优势 = (自身分 − 组内均分) / 组内标准差；
4. 同样用 KL 约束，别偏离参考模型太远。

**最大特点：不需要 PPO 里那个又贵又难训的"价值网络(critic)"，改用"一组样本的平均分"当基线，因此更省、更稳。**

### 5.3 为什么 GRPO 特别慢？

因为每训练一步，都要先让模型**当场生成 G 条、逐 token 自回归输出的回答（这个过程叫 rollout）**，"逐字生成"比"看现成文本训练"慢得多。因此实践中常用小子集、调短生成长度先跑通。

本项目复现的是**纯规则奖励版**（免去下载约 1.8B 的奖励模型），规则只奖励"长度合适、有规范的思考标签、不重复"，因此它主要验证 GRPO 的**机制是否成立**（平均奖励上升、KL 受控、组内优势被拉开），而不直接评判内容对错——这一局限正是第 6 节 RLVR 要补上的。

### 5.4 真实结果（300 步，单卡）

- 设置：600 个 prompt、每个采样 G=4、共 300 步，耗时 21.7 分钟，显存峰值约 9.9GB（rollout 占大头）；
- **组内优势均值严格为 0**（这是 GRPO 的数学性质，可作为实现是否正确的自检）；
- 平均 **|KL| ≈ 0.005**，策略没有偏离参考模型；
- 同 prompt / 同种子前后对比，**规则分 0.109 → 0.290**；在 100 条**未参与训练**的 held-out 题上 +0.084，3-gram 重复度下降；
- 另配 14 项纯 tensor 自检，保证优势归一化、ratio 截断、KL 等张量计算正确。

### 5.5 三种"对齐 / 强化"方法横向对比

|  | SFT | DPO | GRPO |
| --- | --- | --- | --- |
| 数据 | 问题→标准答案 | 问题+好答案+坏答案 | 只要问题，答案模型自己生成 |
| 是否在线生成 | 否 | 否 | **是（慢的根源）** |
| 要不要奖励 / 价值模型 | 不要 | 不要 | 不要价值网络；奖励可规则 / 可验证 / 可模型 |
| 学什么 | 会答题 | 在成对偏好里挑好的 | 自己采样、组内比较着进步 |

## 6. 可验证奖励 RLVR：让"对错"成为奖励，把正确率刷上去

纯规则奖励只改"格式"、不改"对错"。要看到**实打实的正确率提升**，就要用 **RLVR（Reinforcement Learning with Verifiable Rewards）**：在答案能被程序自动判分的任务上（数学、代码单测），**答对给 +1、答错给 0**，不需要奖励模型，也很难被"钻空子"（reward hacking）。

### 6.1 关键前提：先 SFT 到"甜区"，RL 才有用

这是整套实验里最重要、也最反直觉的一条经验：**RL 不注入新知识，只重新分配模型已经具备的能力的概率。**

- 如果模型对某题采样 G 次**全错**，组内奖励全为 0、优势恒为 0、这题就**没有梯度**——RL 再怎么训也教不会它原本完全不会的东西；
- 所以要先用任务专属 SFT，把模型冷启动到"**采样时能偶尔答对**"的半会状态，称为**甜区**，RL 才有东西可以放大。

### 6.2 任务与复现设置

- 任务：一位整数加法（a, b ∈ 1–9，和 ≤ 18），4000 条训练、120 条独立测试（训 / 评无重叠）；
- **SFT 冷启动**：从 full_sft 出发，1 个 epoch（250 步）、lr 1e-5，到达甜区——greedy 正确率 **0.633**、温度采样三种子均值 **0.503**；
- **可验证 GRPO**：B8×G4、lr 4e-6、β-KL 0.08、生成长度上限 16、温度 0.8、CISPO ratio 截断上限 5、bf16、cosine，共 300 步。

### 6.3 真实结果（独立 120 题，多种子）

| 评测口径 | SFT 冷启动 | RLVR 之后 | 提升 |
| --- | --- | --- | --- |
| greedy（温度 0） | 0.633 | **0.792** | +25% |
| 采样 T=0.8（三种子均值） | 0.503 | **0.603** | +20% |

训练过程中 60 题子集的 held-out 正确率从约 0.50 稳步升到 0.80（峰值 0.867），KL 全程受控，训练末值与独立测试结果吻合。原始日志与曲线见 [`../experiments/verifiable_rl/`](../experiments/verifiable_rl)。

### 6.4 三组"失败对照"比成功更有价值

复现中刻意保留了负结果，它们划出了 RL 能力的边界：

1. **任务超出能力边界**：换成两位加法（含进位），模型采样也采不对、组内全错，RL 几乎不动——再次印证"RL 教不会全新知识"；
2. **SFT 训太满**：冷训练到 greedy 0.99，已经到顶，RL 没有提升空间，强推只会震荡；
3. **学习率过大、KL 锚太弱**：lr 8e-6、β 0.02 时发生**策略崩溃**，greedy 从 0.5 崩到 0.03、KL 飘到 −2.9。说明 RL 必须用保守学习率 + 足够强的 KL 锚定。

> 一句话：**数学 / 代码类 RLVR 之所以有效，是因为基座其实已具备推理潜力，RL 只是把这份潜力"激发并稳定"出来。**

## 7. 看懂训练日志：把指标变成可迁移的能力

看任何训练任务，主要盯以下几类信号。

### 7.1 loss 曲线怎么看

- **正常**：整体震荡下行，最后趋于平稳（收敛）；
- **一直不降**：学习率太小 / 数据有问题 / 没接上正确权重；
- **直接爆炸成 NaN 或飞上天**：学习率太大、数值不稳（可换 bf16、加梯度裁剪）；
- **剧烈抖动**：batch 太小（DPO 就是例子），看滑动平均而不是单点；
- **牢记：loss 低 ≠ 回答好**。loss 只反映"拟合训练文本"的程度，生成质量必须另开推理实测（loss 2.2 仍会胡说正是此理）。

### 7.2 资源类指标

- **显存峰值**：决定能不能在这张卡上跑（本项目主链路 4.6–7.4GB，GRPO rollout 阶段约 9.9GB，12GB 卡均可容纳）。省显存手段：bf16、梯度累积、梯度检查点、LoRA、GQA、减小 batch / 序列长度；
- **GPU 利用率**：本项目长期 96–99%，说明 GPU 一直在计算、没被数据加载"饿着"，是健康状态；若长期只有 20–30%，瓶颈就在 CPU / IO；
- **吞吐 tokens/s、每步耗时**：用来估算总训练时长；
- **温度**：长时间满载注意散热（本项目满载约 72–78°C，属正常区间）。

### 7.3 两个思想方法

- **控制变量 / 消融**：想证明"数据量有用"，就只改数据量、其余全不变（small vs medium）；想证明"SFT 有用"，就对比有 / 无 SFT（pretrain-only 测试）；
- **Chinchilla 规律**：模型参数量要和训练 token 数匹配，**小模型也要喂够 token 才不会"营养不良"**。本项目只用了约全量语料的一小部分，所以 63M 小模型仍会出错，这正是该规律的体现，也指明了"喂全量数据 / 换更大模型"的改进方向。

## 9. 名词小词典（随时回查）

- **token**：模型处理文本的最小单位（一个词、子词或字）。
- **参数(parameter)**：模型里可学习的数字，63.91M 即 6391 万个。
- **权重 / checkpoint(.pth)**：训练好的参数存成的文件，即"模型存档"。
- **梯度 / 反向传播**：衡量"每个参数该往哪调、调多少"的机制，可先理解为"改错的依据"。
- **梯度裁剪(grad clip)**：限制一次更新的最大步长，防止某步"用力过猛"训崩。
- **优化器(AdamW)**：按梯度真正去改参数的算法。
- **warmup / cosine**：学习率"先热身升上去、再平滑降下来"的调度策略。
- **fp16 / bf16**：16 位半精度格式，省显存、提速度；bf16 数值范围更大、更不易训崩，优先用。
- **KV Cache**：推理时缓存已算过的 Key/Value，避免重复计算、加快生成；GQA 就是用来压缩它的。
- **tokenizer**：在文字和 token 数字之间互相转换的"词典 + 切词器"。
- **chat template**：规定 system / user / assistant 角色如何拼进模型的固定格式。
- **过拟合**：把训练数据背得太死、遇到新问题反而不行。
- **灾难性遗忘**：学新东西时把旧能力冲没了（所以后段 lr 要小、LoRA 冻结主干、DPO 加 KL 约束）。
- **policy / reference / reward model**：策略=在学的模型；参考=冻结的旧版当锚；奖励模型=专门给回答打分的模型（本项目用规则 / 可验证结果替代了它）。
- **KL 散度**：衡量两个概率分布差多远，训练中用来"别让新模型偏离旧模型太远"。
- **rollout**：用模型实际生成回答的过程（GRPO 慢就慢在这里）。
- **甜区(sweet spot)**：SFT 冷启动到"采样能偶尔答对、但还不稳定"的区间，是 RL 提升空间最大的起点。
