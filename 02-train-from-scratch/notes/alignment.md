## 1. SFT：为什么只对 response 算 loss

### 1.1 目标函数

监督微调本质仍是 next-token 交叉熵，区别在于**用 mask 决定哪些位置参与损失**。一条样本由 prompt（指令）和 response（答案）拼成：

```
tokens = [prompt tokens | response tokens]
mask   = [    0 0 0 ...    |    1 1 1 ...   ]     # prompt 段置 0，response 段置 1

L_SFT = - Σ_t  mask_t · log p( x_t | x_<t )  /  Σ_t mask_t
```

### 1.2 为什么要把 prompt 段 mask 掉

- prompt 是**题目**、不是要模型学习生成的目标，对它算 loss 等于逼模型去"学会生成用户提问"，方向错了；
- 只对 response 算 loss，模型学的是"**给定这样的指令，应该这样回答**"，把预训练的通用语言能力对齐成助手行为。

### 1.3 本项目对照

- SFT 学习率取 1e-5（远小于预训练 5e-4），因为语言能力已具备，只需轻调行为、避免灾难性遗忘；
- 消融现象：只做预训练的模型被要求"写斐波那契"时只会续写一串数字，SFT 后才会以助手身份分点作答、用代码块——这就是 SFT 改变**输出形式**的直观证据；
- 曲线：SFT 5 万步 loss 降到 2.21，且只对 response 计 loss。

## 2. PPO / RLHF：四模型协作，以及为什么不稳定

### 2.1 三个阶段与四个模型

经典 RLHF（InstructGPT）分三步：SFT → 训练奖励模型 RM → 用 PPO 强化优化策略。在线 PPO 阶段同时存在四个模型：

| 模型 | 角色 | 是否更新 |
| --- | --- | --- |
| policy（actor） | 正在对齐的生成模型 | 是 |
| reference | policy 的冻结副本，当锚点 | 否 |
| reward model | 给生成回答打分 | 否（先单独训好） |
| critic（value） | 估计每个状态的价值基线，降方差 | 是 |

### 2.2 带 KL 约束的 RL 目标

RLHF 不让策略为了讨好奖励模型而跑偏，会加一个 KL 惩罚，把策略拴在 reference 附近：

```
max_π  E[ r(x, y) ]  −  β · KL( π(y|x) ‖ π_ref(y|x) )
                  奖励项              别偏离初始模型太远
```

### 2.3 为什么 PPO 难调（工程上的四座大山）

1. **要额外训一个 reward model**，奖励本身有偏差会被策略"钻空子"（reward hacking）；
2. **要再训一个 critic** 做优势估计，模型数量多、显存翻倍；
3. **在线采样 + 多模型前向反向**，每步都要生成，速度慢；
4. 奖励、KL、价值、clip 多个系数耦合，极易训练崩溃，需要精细的超参与 warmup。

DPO 和 GRPO 正是分别从"**去掉 reward model**"和"**去掉 critic**"两个方向给 PPO 做减法。

## 3. DPO（重点）：怎么把一个 RL 目标变成一个分类损失

### 3.1 关键一步：先解出 KL 约束目标的最优策略

对 2.2 的目标做变分，可得到最优策略的闭式解：

```
π*(y|x) = (1/Z(x)) · π_ref(y|x) · exp( r(x,y) / β )
```

反解出奖励（Z(x) 与 y 无关，是归一化常数）：

```
r(x,y) = β · log[ π*(y|x) / π_ref(y|x) ]  +  const
```

含义：**奖励可以用"策略相对参考模型的对数似然提升"来隐式表达**，于是根本不需要一个显式的奖励模型。

### 3.2 构造偏好对，得到 DPO 损失

每条数据是 `(prompt x, 更优回答 y_w, 更差回答 y_l)`。希望策略给 y_w 的相对提升大于给 y_l 的，把上式代入 RL 目标并化简，得到一个二分类式损失：

```
L_DPO = − E[ log σ( β · ( Δ_w − Δ_l ) ) ]

其中  Δ_w = log π_θ(y_w|x) − log π_ref(y_w|x)
      Δ_l = log π_θ(y_l|x) − log π_ref(y_l|x)
      σ 为 sigmoid
```

直观理解：`Δ_w − Δ_l > 0`（好答案相对参考模型提升更多）时损失小，模型被推向"更偏好 chosen、远离 rejected"。

### 3.3 为什么初始 loss 一定是 0.693

训练起点 `π_θ = π_ref`，于是 `Δ_w = Δ_l = 0`：

```
L = −log σ(0) = −log 0.5 = ln 2 ≈ 0.693
```

**本项目 DPO 用 17,166 对偏好数据，日志起点确实在 0.69 附近，随后区间均值 0.642 → 0.620，理论与实验精确吻合**——这是判断 DPO 实现是否正确的一个很好的 sanity check。

### 3.4 β 的作用与本项目取值

- β 越大，`β(Δ_w−Δ_l)` 尺度越大、同时 KL 拴得越紧（越贴近 reference、越保守）；β 越小越敢偏离参考模型；
- 本项目取 β=0.15、学习率 4e-8（对齐阶段最小，只调偏好不动知识）；
- 实验观察：DPO 后回答更简洁收敛，但**本来就写错的内容依然错**——对齐只改偏好/风格、不注入新知识，这一点和第 4 节 GRPO/RLVR 的前提一致。

## 4. GRPO：用"组内比较"替掉 critic

### 4.1 PPO 的 critic 想解决什么

PPO 需要优势函数 `A = return − value`，其中 value 由 critic 网络估计，作用是提供一个**基线**做降方差——只看绝对奖励无法区分"这题本来就简单"还是"这次答得真好"。但为此要额外训练一个和 policy 同量级的 critic，显存和复杂度都高。

### 4.2 GRPO 的核心：同题采样 G 个，用组内均值当基线

GRPO（DeepSeekMath, 2024）对同一个 prompt `q` 一次采样 G 个回答 `{o_1..o_G}`，用**规则/可验证答案**给每个回答打分 r_i，直接在这一组内部做标准化得到优势，完全不需要 critic：

```
A_i = ( r_i − mean(r_1..r_G) ) / ( std(r_1..r_G) + ε )
```

- 均值 `mean` 就是这道题的"动态基线"：比同组平均好，A_i>0 被强化；比平均差，A_i<0 被抑制；
- 除以 std 做归一化，让不同难度题目的梯度尺度可比。

### 4.3 目标函数：PPO clip + 到参考模型的 KL

有了优势后，更新方式沿用 PPO 的截断比率，并加一项 KL 防止跑偏：

```
ρ_i = π_θ(o_i|q) / π_old(o_i|q)                         # 概率比率
J = E[ (1/G) Σ_i min( ρ_i A_i , clip(ρ_i,1−ε,1+ε) A_i ) ] − β · KL(π_θ‖π_ref)
```

### 4.4 三个必须理解的推论（本项目都踩到了）

1. **组内全对或全错时没有梯度**：全对/全错时 std=0、A_i 全为 0，这一步学不到东西。所以必须**先 SFT 到"甜区"**——让采样能偶尔答对、组内有对有错，RL 才有信号。本项目一位加法任务：冷启动 greedy 准确率 0.633，GRPO 后升到 0.792，采样口径 0.503→0.603。
2. **学习率过大会直接崩**：本项目曾因 lr 过大、β 太弱，准确率一度掉到 0.03；RL 阶段学习率必须很小（本项目 4e-8 量级），并靠 KL 把策略拴住（实测平均 |KL|≈0.005，偏离极小）。
3. **慢在 rollout**：每个 prompt 要在线采样 G 条，前向生成是主要耗时。本项目 600 prompt × G=4、300 步耗时 21.7 分钟（约 4.3 s/步），规则分从 0.109 提升到 0.290。

### 4.5 GRPO vs PPO 一览

| 维度 | PPO | GRPO |
| --- | --- | --- |
| 优势基线 | critic 网络估计 value | 同组 G 个回答的均值 |
| 额外模型 | reward model + critic | 都不需要（规则/可验证奖励） |
| 显存 | 4 个模型，最高 | 少一个 critic，明显降低 |
| 适用 | 奖励难自动判定、需 RM | 数学/代码等**答案可验证**任务（RLVR） |
| 代价 | 通用但复杂 | 每 prompt 要采样 G 条，rollout 更慢 |

## 5. 四种对齐方式横向串讲

| 方法 | 数据形式 | 是否在线采样 | 要不要 RM/critic | 本项目关键数字 |
| --- | --- | --- | --- | --- |
| SFT | 指令-答案 | 否 | 都不要 | lr 1e-5，5 万步 loss→2.21 |
| DPO | 成对偏好 (chosen/rejected) | 否 | 都不要（隐式奖励） | 17166 对，β0.15，lr4e-8，loss 0.693→0.62 |
| PPO | RM 打分轨迹 | 是 | 都要 | 本项目未单独实现，作对照 |
| GRPO | 可验证奖励 + 组采样 | 是 | 都不要 | 300 步规则分 0.109→0.290，|KL|≈0.005 |

一条主线记住它们的关系：

- **SFT 教模型"以什么形式回答"**（行为克隆，只对 response 算 loss）；
- **偏好对齐（DPO）教模型"两个回答里更该给哪个"**，用闭式损失绕开 reward model；
- **强化对齐（PPO/GRPO）教模型"朝可量化的奖励方向多探索"**，GRPO 再用组内相对优势绕开 critic；
- 无论哪种，**对齐阶段都不注入新知识**，且学习率逐级减小、用 KL 或冻结锚点防止灾难性遗忘。
