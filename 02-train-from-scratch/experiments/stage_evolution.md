# 五阶段生成横评：同一个问题，看模型如何一步步「学会回答」

> 权重：pretrain / full_sft / lora / dpo / grpo（均为 hidden768、8 层、63.91M）。逐条原始输出见同目录 [`stage_evolution.txt`](stage_evolution.txt)；GRPO 的 100 条定量评测见 [`grpo/eval_100_metrics.txt`](grpo/eval_100_metrics.txt)。

## 1. 实验设置（保证公平，唯一变量是「训练到哪一阶段」）

- 同一组 6 个 prompt（代码 / 常识 / 概念 / 对比 / 生活建议 / 短创作），五个权重使用**完全相同的随机种子与采样参数**（temperature=0.85、top_p=0.95、max_new_tokens=400）。
- pretrain 用 `bos + prompt` 的**续写模式**（它没学过对话模板，强加模板反而不公平）；sft / lora / dpo / grpo 统一走对话模板（open_thinking）。
- lora 不是独立模型，而是叠加在 full_sft 主干上的 **0.78MB 适配器**。

## 2. 总览

| 阶段 | 平均输出字符 | 6 题中闭合 think 标签数 | 一句话定位 |
| --- | ---:| ---:| --- |
| pretrain | 209 | 0 | 会「接话」但不会「答题」 |
| SFT | 544 | 4 | 学会助手角色与结构化表达 |
| LoRA | 522 | 5 | 只训 0.61% 参数即复现 SFT |
| DPO | 529 | 5 | 微调偏好/措辞，不增加知识 |
| GRPO | 517 | 4 | 强 KL 约束下微调格式，不改变知识 |

## 3. 逐阶段：它到底学会了什么

### pretrain —— 只有「语言模型」，没有「指令助手」
- 输出常以「？」「。」「，」等**承接标点开头**：它把 prompt 当成上文在续写，而不是在回答一个用户。
- **不遵循格式要求**：让「用三句话介绍杭州」却写了一大段，反复「壮观的自然景观」，还冒出「金阁寺、泰晤士河」等张冠李戴的景点；「猫狗」题出现「长颈鹿的企鹅」；「明天下雨」给出「2 月 31 日」这种不存在的日期。
- 写斐波那契时函数名是 add/factorial、递归自相矛盾、缩进丢失——有「代码长什么样」的语言先验，但没有正确逻辑。
- **结论**：预训练只灌入语言能力与零星世界知识，不会遵循指令、不会分点、不会 markdown、没有助手身份。

### SFT —— 从「续写」到「对话」的关键一跃
- 学会 chat template、以助手口吻作答、用 ` ```python ` 代码块、先思考再回答（6 题中 4 题产出思维链）。
- 代码结构像模像样（def/for/if 齐全、缩进正确），但 63M 参数 + 少量语料下**逻辑仍不正确**（斐波那契并未写对）——SFT 教的是「怎么答」，不是「答得对」。
- 平均长度 209 → 544，信息组织明显更完整。

### LoRA —— PEFT 性价比的直接证据
- 输出结构、长度（522）、思维链（5/6）与全参 SFT 几乎无差别，而它只训练了 **0.61% 参数**、适配器仅 0.78MB。
- 说明「指令遵循」这类能力用低秩增量即可高效注入，无需全参微调。

### DPO —— 只调偏好，不加知识
- 与 SFT 同档（529 字、5/6 思维链），差异体现在措辞取舍与收敛倾向；DPO 不引入新事实，只让 chosen 风格相对 rejected 更受偏好。

### GRPO —— 强 KL 约束下的小幅格式优化
- 因从 SFT 热启动、训练中 KL 全程≈0（见 [`grpo/metrics.txt`](grpo/metrics.txt)）且只训 300 步，**同种子下输出与 SFT/DPO 高度相似**（如斐波那契一题文本几乎一致，仅结尾措辞不同）——正说明策略被约束在参考模型附近、没有跑偏。
- 规则奖励只对「长度 / 思维链格式 / 不重复」计分，故个别条目的标签闭合、重复度有改善，但**不提升事实/代码正确性**；定量提升见 100 条 held-out 评测。

## 5. 结论

1. 五个阶段**不可互相替代**：pretrain 给「语言底座」、SFT 给「指令/角色」、LoRA 证明「低成本注入」、DPO 调「偏好风格」、GRPO 用奖励做「目标方向的强化」。
2. 能力跃迁最大的是 **pretrain → SFT**（从不会答题到会答题）；之后三个阶段都是在 SFT 基础上做精细化调整。
3. **诚实局限**：63M + 约 5% 全量语料下，五个阶段都无法消除事实错误与代码错误，这是参数量/数据量的限制而非对齐方法的问题，扩大模型与训练 token 才是根本解。
