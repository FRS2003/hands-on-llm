# 垂直领域大模型微调实践方案

> **所属模块**：第 ③ 模块「工业框架」的综合实战，配合 [`../configs`](../configs) 模板与 [`../notes`](../notes) 选型笔记阅读
> **前置知识**：LoRA 与全参微调的区别、基本的数据清洗概念
> **文档定位**：一份在 12GB 消费级显卡上、从零做垂直领域小模型的端到端可执行方案（数据 → 训练 → 评估 → 部署）
> **硬件假设**：3080Ti（12GB 显存）
> **版本**：v2.0 — 两阶段微调策略（LoRA 快速迭代 + 全参数最终优化）

---

## 一、项目概述

### 1.1 项目目标
训练一个专门针对某一垂直领域的小模型，具备以下能力：
- 商品描述生成
- 客服问答
- 营销文案生成
- 评价分析与摘要
- 商品推荐与导购

### 1.2 核心定位
- **小而精**：1.5B 参数，12GB 显存就能跑
- **中文垂直场景适配**：专门针对中文垂直场景优化
- **多任务统一**：一个模型搞定多种领域任务

### 1.3 技术路线（两阶段策略）

**阶段一：LoRA 快速迭代**
- 用 LoRA 做快速实验和调参
- 验证数据、验证思路、验证效果
- 快、省、灵活

**阶段二：全参数最终优化**
- LoRA 阶段效果满意后，做一次全参数微调
- 拿到最好的最终效果
- 发布最终模型

**为什么两阶段？**
- 前期快：LoRA 训练快 2-3 倍，省显存，方便迭代
- 后期好：全参数微调效果最好，没有信息瓶颈
- 有对比：LoRA vs 全参数的对比实验，本身就是项目亮点

## 二、技术选型

### 2.1 基础模型

**首选：Qwen2-1.5B**
- 参数：15 亿（1.5B）
- 中文能力强（阿里通义千问开源）
- 体积小、速度快
- 社区活跃，资料多
- 12GB 显存支持 LoRA 和全参数微调

**备选：Qwen2-0.5B**
- 参数：5 亿（0.5B）
- 更小更快，适合快速实验
- 效果稍差，但够用

**为什么不选 7B？**
- 7B 全参数微调需要 40GB+ 显存，跑不了
- 7B QLoRA 4-bit 能跑，但效果不如 1.5B 全参数
- 1.5B 全参数微调，效果和稳定性都更好

### 2.2 微调方法对比

| 方法 | 更新参数 | 显存（1.5B） | 效果 | 速度 | 适用场景 |
|------|----------|--------------|------|------|----------|
| 全参数微调 | 全部（1.5B） | ~10GB | ⭐⭐⭐⭐⭐ 最好 | 慢 | 最终发布版 |
| LoRA | ~1%（~15M） | ~5GB | ⭐⭐⭐⭐ 很好 | 快 | 快速实验 |
| QLoRA 4-bit | ~1%（~15M） | ~3GB | ⭐⭐⭐ 不错 | 中 | 训更大模型 |

**本方案采用：LoRA + 全参数 两阶段策略**

### 2.3 LoRA 关键参数

| 参数 | 建议值 | 说明 |
|------|--------|------|
| r（rank） | 8-64 | 低秩矩阵的秩，越大效果越好但参数越多 |
| lora_alpha | 16-128 | 缩放因子，通常设为 r 的 2 倍 |
| lora_dropout | 0.05 | 防止过拟合 |
| target_modules | q_proj, v_proj | 要加 LoRA 的层，一般加在注意力的 Q/V 投影 |
| bias | none | 偏置是否训练，一般不训 |

**建议配置**：
- 入门版：r=8, alpha=16, target_modules=["q_proj", "v_proj"]
- 进阶版：r=32, alpha=64, target_modules=["q_proj", "k_proj", "v_proj", "o_proj", "gate_proj", "up_proj", "down_proj"]

> 💡 r 越大，可训练参数越多，效果越好，但显存和训练时间也增加。
> 建议从 r=8 开始，效果不够再加大。

### 2.4 训练框架

**主框架：HuggingFace Transformers + PEFT**
- Transformers：模型加载和训练
- PEFT：LoRA/QLoRA 微调（Parameter-Efficient Fine-Tuning）
- Accelerate：分布式训练（单卡也能用）

**数据处理：Datasets**
- HuggingFace Datasets 库
- 高效的数据加载和处理

**训练工具：TRL**
- Transformer Reinforcement Learning
- 支持 SFT、DPO、PPO、GRPO 等
- 封装得很好，开箱即用

### 2.5 开发环境
- Python 3.10+
- PyTorch 2.0+
- CUDA 12+
- 主要库：transformers、peft、datasets、trl、accelerate、bitsandbytes

## 三、数据准备（最关键的一步）

### 3.1 数据来源

#### 第一类：公开数据集（基础数据）
| 数据集 | 内容 | 规模 | 用途 |
|--------|------|------|------|
| Amazon Reviews | 亚马逊商品评价 | 几亿条 | 评价分析、情感分析 |
| Amazon Product Data | 商品信息 | 几百万 | 商品描述、分类 |
| 公开业务数据集 | 中文领域数据 | 视情况 | 中文垂直场景 |
| Domain Query | 领域搜索查询 | 几十万 | 搜索、导购 |

#### 第二类：合成数据（指令数据）
用 GPT-4 / Claude 等大模型生成分领域任务的"指令-回答"对：
- 商品描述生成：给参数，生成文案
- 客服问答：常见问题和回答
- 营销文案：各种场景的文案
- 评价摘要：一堆评价 → 总结

**生成规模**：先做 5 万条，效果好再扩到 20 万条
**成本估算**：5 万条约 50-100 美元（看用什么模型）

#### 第三类：真实数据（可选，提升真实感）
- 脱敏的客服对话记录
- 真实的商品详情页
- 真实的营销文案

> 💡 建议：先用公开数据 + 合成数据跑通，有条件再加真实数据。

### 3.2 数据处理流程

#### 第一步：数据清洗
- 去重：去掉重复的内容
- 过滤：去掉太短、太长、质量太差的
- 清洗：去掉 HTML 标签、特殊字符、广告等
- 语言过滤：只保留中文

#### 第二步：数据格式化
统一成指令微调格式：
```json
{
  "instruction": "帮我写一个蓝牙耳机的商品标题",
  "input": "品牌：XX；特点：降噪、续航24小时、防水",
  "output": "XX蓝牙耳机 主动降噪 24小时长续航 IPX5防水 运动入耳式"
}
```

#### 第三步：任务分类
按任务类型分类，方便后续混合训练：
- 商品描述生成（30%）
- 客服问答（30%）
- 营销文案（20%）
- 评价分析（10%）
- 导购推荐（10%）

#### 第四步：数据划分
- 训练集：95%
- 验证集：5%（用来监控训练效果）

### 3.3 数据质量控制
- 抽样检查：随机抽 100 条，人工看质量
- 多样性：确保任务多样、风格多样
- 难度分布：有简单的，也有复杂的

## 四、训练方案

### 4.1 阶段一：LoRA 快速迭代

**目的**：快速验证数据、调参、找最优方案

#### 4.1.1 LoRA SFT 训练

**数据**：领域指令数据集
- 规模：先 1 万条试水，效果好再加到 5-20 万条

**超参数建议**：
| 参数 | 建议值 | 说明 |
|------|--------|------|
| LoRA rank | 8-32 | 从 8 开始，不够再加 |
| LoRA alpha | 16-64 | 一般是 rank 的 2 倍 |
| target_modules | q_proj, v_proj | 入门版；进阶版加更多层 |
| 学习率 | 1e-4 ~ 3e-4 | LoRA 的学习率比全参数大 |
| Batch size | 16-32 | LoRA 省显存，可以开大 |
| 序列长度 | 2048 | 大部分任务够了 |
| 训练轮数 | 3-5 轮 | 太多容易过拟合 |
| 优化器 | AdamW | 标配 |
| 精度 | bf16 混合精度 | 省显存 + 快 |

**显存占用**：~5GB（非常宽松）

**训练时间估算**：
- 5 万条数据，1.5B 模型，3 轮
- 大约 5-10 小时
- 成本：10-20 块钱

#### 4.1.2 LoRA 阶段要做的实验

在 LoRA 阶段，多做实验，找最优配置：

1. **数据量实验**：1 万 vs 5 万 vs 10 万，效果差多少？
2. **LoRA rank 实验**：r=8 vs r=32 vs r=64，效果差多少？
3. **任务比例实验**：不同任务的比例怎么调最好？
4. **学习率实验**：什么学习率效果最好？
5. **数据清洗实验**：清洗前后效果差多少？

> 💡 这些实验记录下来，就是很好的技术博客内容，也是项目的亮点。

---

### 4.2 阶段二：全参数最终优化

**目的**：LoRA 阶段找到最优配置后，做一次全参数微调，拿到最好的最终效果

#### 4.2.1 全参数 SFT 训练

**数据**：用 LoRA 阶段验证过的最优数据集
- 规模：5-20 万条

**超参数建议**：
| 参数 | 建议值 | 说明 |
|------|--------|------|
| 学习率 | 2e-5 | 比 LoRA 小一个数量级 |
| Batch size | 8-16 | 全参数显存大，开小一点 |
| 序列长度 | 2048 | 和 LoRA 阶段保持一致 |
| 训练轮数 | 2-3 轮 | 全参数更容易过拟合 |
| 优化器 | AdamW | 标配 |
| 精度 | bf16 混合精度 | 省显存 + 快 |

**显存优化技巧**（全参数必须用）：
1. **梯度检查点**（Gradient Checkpointing）：省 60% 显存，慢 30%
2. **梯度累积**（Gradient Accumulation）：模拟大 batch
3. **混合精度训练**（bf16）：省一半显存
4. **8-bit 优化器**：再省一点

**显存占用**：~10GB（留 2GB 余量）

**训练时间估算**：
- 5 万条数据，1.5B 模型，3 轮
- 大约 10-20 小时
- 成本：20-40 块钱

#### 4.2.2 领域继续预训练（可选，但推荐）

在 SFT 之前，可以先做一步领域继续预训练：

**目的**：让模型先熟悉目标领域的语言和知识

**数据**：目标领域的无标注文本（业务描述、评价、文章等）
- 规模：5000 万 - 1 亿 tokens
- 格式：纯文本

**方法**：
- 因果语言建模（CLM）—— 就是普通的语言模型训练
- 学习率：比预训练小一个数量级
- 步数：1000-3000 步

**效果**：
- 模型更懂领域的"行话"
- 生成的文案更贴合领域风格
- 后续 SFT 效果更好

**显存占用**：~10GB

---

### 4.3 阶段三：对齐优化（可选，进阶）

**目的**：让模型生成的内容更符合人类偏好

**方法一：DPO（直接偏好优化）**
- 准备偏好数据：好的回答 vs 差的回答
- 用 DPO 算法优化
- 简单、稳定、效果好

**方法二：GRPO（组相对策略优化）**
- 用可验证的奖励（比如文案评分）
- 用 GRPO 算法优化
- 适合有明确评价标准的任务

**效果**：
- 生成的文案更吸引人
- 回答更准确、更有用
- 整体体验更好

**显存占用**：~10GB（全参数）/ ~5GB（LoRA）
**训练时间**：几小时

---

### 4.4 训练监控

**必看指标**：
- 训练损失（Training Loss）：应该持续下降
- 验证损失（Validation Loss）：先降后升，升了就是过拟合了
- 学习率曲线

**定期评估**：
- 每 500 步在验证集上跑一下
- 抽几个例子人工看看效果

**保存检查点**：
- 每 1000 步保存一次
- 保留最好的 3 个检查点

## 五、评估方案

### 5.1 自动评估（客观指标）

| 任务 | 评估指标 | 说明 |
|------|----------|------|
| 商品描述生成 | BLEU、ROUGE | 和参考答案对比 |
| 客服问答 | 准确率、F1 | 看答案对不对 |
| 评价分析 | 准确率、F1 | 分类任务好评估 |
| 通用 | 困惑度（Perplexity） | 越低越好 |

### 5.2 人工评估（主观指标）

自动指标不够，一定要人工评估：

**评估维度**：
1. **相关性**：回答和问题相关吗？
2. **准确性**：信息准确吗？有没有胡说八道？
3. **有用性**：真的有用吗？能解决问题吗？
4. **流畅性**：读起来顺吗？像人写的吗？
5. **风格**：符合领域风格吗？

**评估方法**：
- 抽 50-100 个例子
- 自己打分，或者找朋友帮忙
- 和通用模型（比如 Qwen-1.5B 原版）对比

### 5.3 对比实验（重点！）

一定要做对比，才能体现你的模型的价值：

**对比对象**：
1. Qwen-1.5B 原版（通用模型 baseline）
2. Qwen-1.5B + LoRA（你的 LoRA 版本）
3. Qwen-1.5B + 全参数微调（你的最终版本）
4. Qwen-7B（更大的通用模型，可选）

**对比维度**：
- 效果：谁的回答更好？（人工打分）
- 速度：谁更快？
- 显存：谁占的显存少？
- 参数效率：同样参数下，谁的效果更好？

> 💡 这个对比实验本身就是项目的一大亮点！
> 很多人都好奇 LoRA 和全参数微调到底差多少，你做出来了，就是有价值的贡献。

## 十、风险与应对

| 风险 | 概率 | 影响 | 应对方案 |
|------|------|------|----------|
| 数据质量差 | 中 | 高 | 多花时间清洗，抽样检查 |
| 训练不稳定 | 低 | 中 | 降低学习率，加 warmup |
| LoRA 效果不够好 | 中 | 中 | 加大 rank，加更多 target modules |
| 全参数显存不够 | 低 | 中 | 减小 batch size，用梯度累积 |
| 过拟合 | 高 | 中 | 早停、加数据增强、增大数据量 |
| 效果不如预期 | 中 | 中 | 加数据、调参数、换基础模型 |
